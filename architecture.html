Architecture Reference

Factory Inventory Management System

Full-stack demo — Vue 3 frontend, Python FastAPI backend, in-memory JSON data

Vue 3 FastAPI Vite Axios Pydantic Frontend: :3000 Backend: :8001

Tech Stack

Frontend
  • Vue 3 — Composition API throughout
  • Vue Router — 7 client-side routes
  • Axios — HTTP client, centralized in api.js
  • Vite — Dev server & bundler, port 3000
  • Custom SVG charts, CSS Grid layouts
Backend
  • FastAPI — REST API, CORS enabled
  • Uvicorn — ASGI server, port 8001
  • Pydantic v2 — Request/response validation
  • uv — Python package manager
  • No database — all data held in memory
Data Layer
  • 6 JSON files in server/data/
  • Loaded once into memory on startup via mock_data.py
  • No persistence — writes lost on restart
  • In-memory filtering via Python list comprehensions
  • ~100+ orders, 20+ inventory items, 100+ transactions
UX / i18n
  • EN / JP locale toggle, persisted to localStorage
  • USD / JPY currency formatting
  • Composables: useFilters, useAuth, useI18n
  • Global filter state shared across all views
  • No external UI framework — custom component library

Filter Data Flow

Filtered Endpoints (Dashboard, Inventory, Orders)

1
User changes a filter
FilterBar.vue updates a ref in useFilters.js (selectedPeriod, selectedLocation, selectedCategory, selectedStatus)
2
View watcher fires
watch() in the active view detects the filter ref change and calls loadData()
3
Filters mapped to API params
getCurrentFilters() returns { warehouse, category, status, month } — UI labels mapped to API param names
4
HTTP request dispatched
api.js builds query string:
GET /api/orders?warehouse=Tokyo&status=Delivered
5
Backend filters in memory
apply_filters() chains warehouse → category → status. filter_by_month() handles Q1-2025 → ['2025-01','2025-02','2025-03']
6
Vue re-renders
Response updates view's ref → computed properties recalculate → DOM updates reactively

Unfiltered Endpoints (Demand, Backlog, Spending, Reports)

1
View mounts
onMounted() calls loadData() once — global filters are ignored for these views
2
Fixed request sent
No query params: GET /api/demand, GET /api/backlog, GET /api/spending/summary, etc.
3
Full dataset returned
Backend returns all records. View applies any local UI filtering (e.g., search box in Inventory)
4
Computed properties derive display data
Totals, percentages, chart data, trend groupings — all computed from raw refs, never stored separately
Loading State Pattern
Every view follows:
loading = true → try fetch → data.value = result
→ catch → error.value = msg → finally loading = false

API Endpoints

Method Path Filter Params Description
GET /api/dashboard/summary warehouse category status month Aggregated KPIs — inventory value, low stock count, pending orders, backlog total, orders value
GET /api/inventory warehouse category All inventory items — SKU, quantity, reorder point, unit cost, location, status
GET /api/inventory/{item_id} — Single inventory item by ID (404 if not found)
GET /api/orders warehouse category status month Customer orders with embedded line items — supports quarter format (Q1-2025)
GET /api/orders/{order_id} — Single order by ID
GET /api/demand — Demand forecasts — current vs forecasted demand, trend classification
GET /api/backlog — Backlog shortages — adds has_purchase_order flag computed at runtime
GET /api/spending/summary — Aggregate cost totals — procurement, operational, labor, overhead + % change vs prior period
GET /api/spending/monthly — 12-month cost breakdown by type (procurement / operational / labor / overhead)
GET /api/spending/categories — Total spend grouped by product category
GET /api/spending/transactions — Individual transaction ledger — date, vendor, category, amount, warehouse
GET /api/reports/quarterly — Quarterly rollups — total orders, revenue, delivered count, avg order value, fulfillment rate
GET /api/reports/monthly-trends — Monthly trends — order count, revenue, delivered count per month
POST /api/purchase-orders — Create a purchase order linked to a backlog item (in-memory only, not persisted)

Data Entities

InventoryItem inventory.json
  • id, skustring — primary key
  • name, category, warehousestring
  • quantity_on_hand, reorder_pointint
  • unit_costfloat
  • location, last_updatedstring
Referenced by Order.items[].sku, DemandForecast.item_sku, BacklogItem.item_sku
Order orders.json
  • id, order_numberstring — primary key
  • customer, warehouse, categorystring
  • itemsarray — [{sku, name, qty, unit_price}]
  • statusDelivered | Shipped | Processing | Backordered
  • order_date, expected_delivery, actual_deliveryISO 8601
  • total_valuefloat
items[].sku → InventoryItem.sku  ·  Referenced by BacklogItem.order_id
DemandForecast demand_forecasts.json
  • idstring — primary key
  • item_sku, item_namestring
  • current_demand, forecasted_demandint
  • trendincreasing | stable | decreasing
  • periodstring — "Next 30 days"
item_sku → InventoryItem.sku
BacklogItem backlog_items.json
  • idstring — primary key
  • order_id, item_sku, item_namestring

  • days_delayedint

order_id → Order.id  ·  item_sku → InventoryItem.sku
